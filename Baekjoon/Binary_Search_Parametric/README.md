# 🪚 Parametric Search (파라메트릭 서치)

이분 탐색(Binary Search)의 뼈대를 활용하여, **"최적화 문제"**를 **"결정 문제(Yes/No)"**로 뒤집어서 푸는 강력한 알고리즘입니다. 

## 💡 핵심 철학 및 트러블 슈팅 가이드

단순히 배열에서 특정 값을 찾는 기본 이분 탐색과 달리, 파라메트릭 서치를 설계할 때는 다음 3가지 함정을 반드시 통제해야 합니다.

**1. 탐색 공간(Search Space)의 재정의**
- `left`와 `right`는 배열의 '인덱스'가 아닙니다!
- 우리가 조절해야 하는 **'정답의 가능한 범위(예: 톱의 높이 0 ~ 최대 나무 높이)'** 자체를 `left`와 `right`로 설정해야 합니다.

**2. 왜 `==` 대신 부등호(`>=`, `<=`)를 쓰는가?**
- 조건에 딱 맞아떨어지는 값이 아예 존재하지 않을 수 있습니다.
- 우리는 '정확한 값'이 아니라, '조건을 만족하는 선에서의 최댓값(또는 최솟값)'을 구해야 하므로 반드시 부등호로 범위를 좁혀야 합니다.

**3. `best_answer`의 진짜 역할 (안전망 확보)**
- 조건을 만족했다고 해서 즉시 `return`하면 안 됩니다. 그 값이 한계치(최적값)라는 보장이 없기 때문입니다.
- 조건을 만족할 때마다 `best_answer`에 임시로 기록(Checkpoint)해 두고, 루프가 끝날 때까지 더 욕심을 내어 탐색을 이어가야 합니다.
